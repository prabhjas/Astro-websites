# Owner / ops only — Dynamic GTM & GA4

**Audience:** you (fleet owner / ops). **Not** a day-to-day developer checklist.  
Do **not** add this as a phase in `00-NEW-SITE-MASTER.md` — keep GTM/GA4 ownership here so developers do not paste tags into page/post HTML.

Run this **at the end** of a site go-live (after content + forms + Caddy), or when rotating containers.

---

## Rule (non-negotiable)

| Do | Do not |
|----|--------|
| Serve tags via **`/runtime-gtm.js`** (dynamic loader) | Paste GTM/GA4 `<script>` / noscript into pages, posts, legacy HTML, headers, footers |
| Put interim IDs in **`.env` / `.env.prod`** | Commit live container IDs into git-tracked HTML |
| Let **FLOW** override via `.data/internal-admin/gtm.json` | Leave WP Rocket / static WP embeds in cleaned HTML without stripping |

Inject path (fleet pattern):

1. HTML gets only: `<script src="/runtime-gtm.js" defer data-runtime-gtm="1"></script>`
2. Legacy mirrors run `injectRuntimeGtmLoader()` which **strips** old googletagmanager embeds, then adds the loader
3. `/runtime-gtm.js` resolves effective snippets at **request time** (not baked into every page file)

Shared resolver: `@connect/site-cms` → `resolveEffectiveGtmConfig`  
(`packages/site-cms/src/gtm/store.ts`)

---

## Priority (what wins)

1. **FLOW file** — `.data/internal-admin/gtm.json` (if any head/body/footer snippet is non-empty)  
   → this **overrides** env once FLOW saves tags
2. **Optional raw env snippets** — `GTM_HEAD_SCRIPT` / `GTM_BODY_HTML` / `GTM_FOOTER_SCRIPT`
3. **ID lists** — `PUBLIC_GTM_ID` + `PUBLIC_GA4_ID` → standard snippets generated by the package
4. **none** — loader still returns JS, but injects nothing

So: env is the interim source; FLOW is the long-term source of truth for that domain.

---

## Interim env (before / until FLOW UI)

Laptop `.env` and server `.env.prod` (or build `.env` where you keep public IDs):

```bash
# One or more, comma / space / semicolon separated
PUBLIC_GTM_ID=GTM-AAAA,GTM-BBBB
PUBLIC_GA4_ID=G-XXXX,G-YYYY
```

Notes:

- Both can be set; loader injects every valid ID
- A lone `G-…` in `PUBLIC_GTM_ID` is accepted as GA4 if no `PUBLIC_GA4_ID`
- Aliases also accepted: `GTM_CONTAINER_ID`, `GA4_MEASUREMENT_ID`, `PUBLIC_GA_MEASUREMENT_ID`
- **Do not** put secrets in `PUBLIC_*` — only container / measurement IDs

`PUBLIC_*` is inlined at Astro build for some paths; after changing IDs on a site that already ships a build, **rebuild + restart** (or rely on runtime `resolveEffectiveGtmConfig` from process env / FLOW file — prefer restart after `.env.prod` change).

---

## FLOW override

When FLOW is wired for the domain:

- Dashboard writes via `GET/POST /api/internal/gtm/` (+ `/save`)
- File: `.data/internal-admin/gtm.json` (gitignored runtime)
- As soon as that file has snippets, **env IDs are ignored** until the file is cleared

Ops implication: if tags look “stuck”, check whether `gtm.json` exists and wins over `.env.prod`.

## Final checklist (run yourself per site)

Replace `<id>`, `<port>`, `<domain>`, expected `GTM-…` / `G-…`.

### A. No static tags in content

```bash
cd Astro-production/<domain>

# Should be empty (or only comments / stripped leftovers). Fail if live GTM-/G- scripts sit in mirrors.
grep -RIn --include='*.html' --include='*.astro' -E 'googletagmanager\.com/(gtm\.js|gtag/js|ns\.html)|GTM-[A-Z0-9]+' \
  src/legacy public src/pages 2>/dev/null | grep -v runtime-gtm | grep -v 'data-runtime-gtm' | head
```

Expect: no hard-coded containers in page/post bodies. Loader-only is OK.

### B. Loader present

```bash
curl -sS "http://127.0.0.1:<port>/" | grep -o 'data-runtime-gtm="1"' | head -1
# expect: data-runtime-gtm="1"
```

### C. Runtime resolves expected IDs

```bash
curl -sS "http://127.0.0.1:<port>/runtime-gtm.js" | grep -oE 'GTM-[A-Z0-9]+|G-[A-Z0-9]+' | sort -u
```

### D. Source of truth

| Situation | Expect |
|-----------|--------|
| No FLOW file yet | IDs match `.env` / `.env.prod` |
| FLOW saved tags | `/runtime-gtm.js` matches `gtm.json`, **not** stale env if they differ |

```bash
# Server (ops)
# ls /opt/Astro-production/<domain>/.data/internal-admin/gtm.json
# If present and non-empty snippets → FLOW wins
```

### E. Public HTTPS (after deploy)

```bash
curl -sS "https://<canonical>/" | grep -o 'data-runtime-gtm="1"' | head -1
curl -sS "https://<canonical>/runtime-gtm.js" | grep -oE 'GTM-[A-Z0-9]+|G-[A-Z0-9]+' | sort -u
```

### F. Cache

`/runtime-gtm.js` is `Cache-Control: no-store`. If Cloudflare still serves old JS, purge that URL path only.

## New site wiring (ops review — not developer freestyle)

When a new scaffold lands, confirm peers already have:

| Piece | Typical path |
|-------|----------------|
| Runtime endpoint | `src/pages/runtime-gtm.js.ts` |
| Strip + inject | `src/lib/gtm/inject.ts` (+ call from legacy/chrome layouts) |
| Store / resolve | site `src/lib/gtm/store.ts` re-export or `@connect/site-cms` |
| Internal API | `src/pages/api/internal/gtm/` (+ `save`) when `FEATURES_FULL_CMS` |
| Env template | `.env.example` → `PUBLIC_GTM_ID` / `PUBLIC_GA4_ID` blank |

Copy from a known-good peer: `connectgroup.co`, `evolutionmiddleast.com`, or `spheavyrental.ae`.

Developers may leave IDs blank in `.env.example`. **You** set live IDs on the server / FLOW at cutover.
